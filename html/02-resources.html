第2章 教材、视频与工具#

← 返回章节目录 · 查看 HTML 版

官方教材、主线课程、补充视频、题库和实践工具。

3. 教材、视频、题库与工具#

3.1 必备教材：只买这三本即可开始#

优先级资料用法
必备《系统架构设计师考试大纲》，全国计算机专业技术资格考试办公室编，清华大学出版社，ISBN 9787302620037第一周通读；每个阶段开始前用它确认边界；不要拿辅导班讲义替代大纲
必备《系统架构设计师教程（第 2 版）》，叶宏、鲍亮、宋胜利、蔺一帅，清华大学出版社，ISBN 9787302619925全程主教材；第一遍建立框架，第二遍结合真题回查，第三遍只看薄弱章节
推荐《系统架构设计师 2018 至 2022 年试题分析与解答》，计算机技术与软件专业技术资格考试研究部，清华大学出版社，ISBN 9787302674269作为权威真题解析；2023 年后的题另从可靠题库补充

可选资料：

  • 《系统架构设计师考试全程指导（第 2 版）》可用于操作系统、数据库、案例和论文的补充解释，但出版较早，不能替代新版大纲与新版教程。
  • 不需要同时购买多套“5 天通关”“背诵宝典”“押题密卷”。最后两个月确有需要时，再选择一本压缩记忆资料。
  • 不使用来历不明的盗版 PDF、所谓“内部题”和只给结论不给出处的答案。

3.2 主线视频：选择一套，完整跟随#

免费主线候选：

  • 青石竹屋：系统架构师教程（综合知识、案例、论文）

它适合作为第一遍框架课，但视频标题中的年份不代表官方教材版本发生了更新。观看时必须以官方教程第 2 版目录为索引：视频与教材冲突时以官方大纲、教程和最新正式通知为准。

如果免费课程试听 3～5 节后明显不适应，可以选择正规机构的新版系统课，但只在以下情况考虑付费：

  • 自学连续三周无法维持进度。
  • 需要作业批改、论文批改或固定直播约束。
  • 课程明确对应 2022 年审定大纲和教程第 2 版，并覆盖案例、论文、机考训练。

购买前必须试听“系统质量属性与架构评估”和“案例分析”两节。能否讲清原理和答题理由，比宣传通过率重要。

3.3 零基础补课视频：遇到对应月份再看，不要一次收藏后全部开学#

模块推荐视频只需重点观看
计算机组成王道计算机考研：计算机组成原理；需要更深入理解时参考哈工大刘宏伟课程数据表示、存储层次、Cache、指令与流水线、中断、DMA；不做考研难题
操作系统王道计算机考研：操作系统进程线程、调度、同步互斥、PV、死锁、内存、页面置换、文件和 I/O
数据结构王道计算机考研：数据结构复杂度、线性结构、树、图、查找、哈希、排序；代码用 TypeScript 自己实现小例子
计算机网络王道计算机考研：计算机网络；图示理解可参考湖科大计算机网络分层、交换、IP/子网、路由、TCP/UDP、DNS、HTTP、常见安全协议
数据库哈工大战德臣：数据库系统关系模型、关系代数、SQL、范式、事务、并发、恢复、索引和查询优化
操作系统进阶南京大学蒋炎岩：2025 操作系统原理仅当基本概念仍无法理解时选看进程、地址空间、文件系统；它很优秀，但明显超出软考所需深度

视频使用原则：

  • 1.25～1.5 倍速观看，暂停画图和做题的时间不计入视频时长。
  • 一个知识点看 30～60 分钟仍不懂时，换一次解释来源；不要连续换五套课程。
  • 补课视频只为解决具体难点，不要求“全集打卡”。
  • 每看完一个小节，至少完成 5～10 道对应题或一个小实验。

3.4 真题与题库#

真题按三层使用：

  1. 章节练习题：学完一个知识点立即做，目的是暴露理解问题。
  2. 分类真题：完成一个模块后做，目的是认识命题方式。
  3. 完整年度真题：中后期按时间完成，目的是训练取舍和节奏。

真题年份分配：

  • 2016—2020：用于第一轮分类练习和早期摸底。
  • 2021—2023：用于强化和案例专项。
  • 2024—2026：留到 2027 年 6 月以后做整套模拟。
  • 2027 上半年：若当年正常开考并有可靠回忆题，留到考前 6～8 周做最后校准。

选择在线题库时检查四点：标明考试年份、答案有解释、错误可以收藏、解析出现争议时能查看多个来源。机构回忆题可能不完整，不能把单一来源当成官方原题。

3.5 实践工具#

实践项目优先使用已经熟悉或容易上手的工具：

  • TypeScript + Node.js（Express、Fastify 或 NestJS 任选其一）。
  • PostgreSQL 或 MySQL，选择一种即可。
  • Redis。
  • RabbitMQ；如果已经熟悉 Kafka，也可以替换。
  • Nginx。
  • Docker Compose。
  • k6 或 Apache JMeter 做简单压力测试。
  • Mermaid、draw.io 或 PlantUML 画图。
  • Git 管理实践与笔记。

不要把时间耗在框架选型。实践项目的评分标准是能说明需求、架构、权衡和结果，不是代码量。
