第3章 学习方法、时间与阶段#

← 返回章节目录 · 查看 HTML 版

学习闭环、笔记系统、标准周安排和阶段验收。

4. 学习闭环与笔记系统#

4.1 每个知识单元采用“学—画—题—讲—复盘”#

  1. 学：看官方教程和主线视频，首次接触时只抓概念、关系和典型应用。
  2. 画：画一张结构图、流程图或对比表。
  3. 题：完成 10～30 道章节题，案例模块至少做一道主观题。
  4. 讲：不看资料，用 3 分钟向“没有后端经验的前端同事”解释它。
  5. 复盘：在第 1、3、7、14、30 天回顾，直到能主动回忆。

4.3 错题记录格式#

每道错题只记录这些内容：

题目来源：年份 / 科目 / 题号
知识点：
我的答案与理由：
正确答案与理由：
错误类型：概念不清 / 混淆 / 计算错误 / 审题错误 / 时间不足 / 完全陌生
最小纠正结论：一句话写清
关联知识：
复习日期：D1 / D3 / D7 / D14 / D30

如果只抄题和答案，错题本很快会变成另一本不会看的题库。

4.4 记忆策略#

  • 需要理解：进程与线程、事务隔离、架构风格、质量属性、分布式一致性。
  • 需要“理解后记忆”：开发模型、UML 图用途、安全机制、可靠性公式。
  • 可以直接记忆：标准、法律、知识产权年限、专业英语、高频名词。
  • 任何需要背诵的内容都先做成问题，例如“可用性常用架构策略有哪些”，不要复制一整段课文。

5. 每周时间安排#

5.1 标准周：8～10 小时#

时间内容时长
周一主线课程 + 教材对应章节60 分钟
周二主线课程 + 结构图或对比表60 分钟
周三章节题 15～25 道 + 错题复盘60 分钟
周四补充课程或案例知识60 分钟
周五休息；只做 15 分钟闪卡或英语0～30 分钟
周六重点学习、案例或真题2.5～3 小时
周日架构实践、论文素材、周复盘2～2.5 小时

工作日采用 50 分钟专注 + 10 分钟回忆。周末每 90 分钟休息 15 分钟。

5.2 忙碌周：最低 4 小时#

不能正常执行时，只保留：

  • 90 分钟主线教材/视频。
  • 60 分钟章节题。
  • 60 分钟错题与主动回忆。
  • 30 分钟论文素材或案例关键词。

忙碌周结束后不熬夜补齐全部视频。先补本周验收项，再继续下一周。

5.3 冲刺周：12～15 小时#

从 2027 年 8 月起逐步提高到：

  • 工作日每天 1～1.5 小时。
  • 周六 4 小时连考训练。
  • 周日 2 小时论文 + 2 小时复盘。

6. 阶段总览#

阶段周期核心任务阶段验收
P0 启动与诊断W01～W02了解考试、准备资料、做基线测试、建立笔记系统完成一套摸底；形成个人差距表和真实项目清单
P1 计算机与软件基础W03～W19组成、操作系统、数据结构、网络、数据库模块题正确率达到 60%；能画出 Web 请求全链路
P2 软件工程与架构核心W20～W36软件工程、UML、安全、架构风格、质量属性、评估、可靠性混合选择题达到 50 分左右；案例开始形成规范表达
P3 专题架构与第一轮真题W37～W45信息系统、分层、云原生、SOA、微服务、安全、大数据架构官方教程完成第一轮；至少完成 3 套整题和 8 道案例
